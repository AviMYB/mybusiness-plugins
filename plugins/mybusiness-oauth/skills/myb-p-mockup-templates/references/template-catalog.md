# Template catalog

## Interactive starter

Each route has an editable `assets/prototype/pages/<name>.js` module. Shared navigation,
modal lifecycle, state and actions live in `app.js`; sample data in `data.js`; visual styling
in `app.css`. Use the scaffolder so relative links and original references are copied correctly.

| Route / module | Useful for | Working behavior |
|---|---|---|
| `records` | Lists, queues, record cards | Search, status filter, sorting, pagination, create/edit side sheet, required/email/number validation, save/cancel, error/retry |
| `dashboard` | Management overview | Team filter, calculated KPIs and bar chart, shared record state |
| `settings` | Tile landing and preferences | Team default, notification toggle, initial-dashboard preference, save/cancel |
| `kanban` | Pipeline with sample stages | Move cards by drag/drop or accessible select; shared status and counters |
| `calendar` | Weekly hourly grid | Week navigation, event create/edit, required date/time fields |
| `wizard` | Proposed guided setup/intake | Three steps, retained draft on back, validation, review, local completion |
| `document` | Proposed line-item editor | Add/remove rows, quantities/prices, discount and calculated total, draft save/cancel |
| `inbox` | Conversation concepts | Search, select thread, separate drafts, local message append, no sending |
| `reports` | Proposed report builder | Column selection, status filtering, explicit run, local CSV export |
| `import` | Proposed import review | Bundled synthetic fixture, valid/invalid rows, cancel/commit, duplicate-commit guard |
| `activity` | Activity center | Local activity feed generated by actions, search and no-results state |
| `knowledge` | Help/training center | Search, category filter, article dialog, no-results state |

`gallery` is the launchpad for all twelve patterns. These are prototype interactions, not
a catalogue of guaranteed native CRM capabilities. Core CRM layouts were compared against the live product on 2026-09-20. Remaining patterns are proposals. The gallery is outside the CRM shell. Verify the target screen before claiming exact fidelity.

## Original visual-reference templates

The 14 original HTML files remain under `assets/<module>/`. The generated prototype copies
them to `reference-pages/<module>/`. These are static references and keep placeholder labels;
they are not counted as fully interactive experiences.

| Module / shell | Templates |
|---|---|
| `mybusiness` / CRM | `list-page.html`, `record-card-modal.html`, `settings-landing.html`, `settings-table-page.html`, `settings-form-page.html`, `dashboard-page.html`, `dashboard-leads.html`, `dashboard-sales-manager.html` |
| `mybooks` / module | `mybooks-dashboard.html`, `mybooks-documents.html` |
| `mychat` / CRM | `mychat-conversations.html` |
| `mycampaigns` / module | `mycampaigns-dashboard.html` |
| `mycollege` / CRM | `mycollege-dashboard.html` |
| `timesheet` / module | `timesheet-dashboard.html` |

For a module-specific prototype, copy that module's shell and wire the interactive state
contract into its content. The starter's default CRM shell does not establish a match to
MyBooks, MyCampaigns or TimeSheet. Original references use optional Google Fonts/FontAwesome
CDNs; the interactive starter uses inline SVG icons and bundled Assistant/Heebo fonts without network access. See asset-provenance.md.

## Minimal customization map

1. Keep only requested routes in `catalog.js` and remove unused view imports/registrations.
2. Put invented fixtures in `data.js`; change the storage namespace in `config.js` for a new project.
3. Adapt the page module and its event handlers together. Rendering alone does not make a control work.
4. Record proposed behavior and outstanding native-product verification in the handoff.
5. Run the primary journey at both desktop and mobile widths before delivery.
